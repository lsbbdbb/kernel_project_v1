🎯 项目目标

自动将上游 Linux 内核 CVE 修复补丁转化为目标内核（Anolis OS 6.6.102）的可加载 livepatch .ko 模块，全程无需人工介入。

🔁 工作流程

  1. CVE 解析 — 从 NVD 和 Linux stable 仓库获取 CVE 元数据与补丁链接
  2. 补丁获取 & 解析 — 下载原始 unified diff，解析为结构化的中间表示（patch_ir + change_units）
  3. 目标检查 — 验证目标内核源码树是否存在，检查 Kbuild Makefile 追踪 patched 对象是否被配置禁用
  4. 补丁应用 & 构建 — 在目标内核上 dry-run 检查补丁可应用性，然后用 kpatch-build 编译 livepatch .ko
  5. 失败分类 — 当构建失败时，用 19 种预定义模式（+ YAML 规则）对构建日志进行归因
  6. 自动重写 — 基于失败原因选择 6 种改写策略（context_drift / api_mismatch / missing_include / struct_abi / data_change / no_fentry），可选 LLM 辅助生成
  7. 验证 — 在目标 VM（SSH）中加载 .ko，检查 sysfs 状态，执行可选的 PoC 验证
  8. 报告生成 — 输出结构化 report.json + summary.json

🧠 智能决策

项目支持两级决策：

  • 规则模式（--no-llm）— 纯确定性状态机 + YAML 规则驱动，适合无 API key 的环境
  • LLM 增强模式（默认）— 在失败分类后咨询 LLM（DeepSeek/OpenAI/Ollama），辅助选择改写策略和生成重写 diff

安全护栏：非可重试故障（struct_abi / no_fentry 等）即使 LLM 建议改写也强制转人工。

🏗️ 架构

  • 状态机 — 18 个预定义状态，JSON 持久化每次转移
  • Planner — 决定每个 CVE 的下一步 action，支持 LLM 辅助决策
  • 工具链 — 10 个独立工具（resolver / fetcher / parser / builder / classifier / advisor / verifier / reporter / config-checker / semantic-validator）
  • RAG 知识库 — BM25 检索器，索引 YAML 规则 + 内核 API 变更 + kpatch FAQ 文档
  • 语义验证器 — 重写后的 patch 自动检查安全语义是否保持（安全检查、错误返回路径、内存泄漏等）

🛡️ 安全约束

  • 不会修改 __init / __exit 函数
  • 不会引入新的全局变量或 EXPORT_SYMBOL
  • 不会移除原始 patch 中的安全检查（if (!ptr) / WARN_ON 等）
  • 不会泄露 shadow 变量或动态分配内存
  • 非可重试故障强制转人工，LLM 不能覆盖此安全门
